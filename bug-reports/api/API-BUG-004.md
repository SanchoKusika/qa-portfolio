# API-BUG-004. [POST /pet] Сервер создает питомца без обязательных полей и с id, который ломается в JavaScript

| Поле | Значение |
|---|---|
| Severity | Major |
| Priority | High |
| Endpoint | `POST /v2/pet` |
| Окружение | https://petstore.swagger.io/v2, Newman 6.2.1 (Node.js 24), cURL |
| Дата | 2026-10-12 |
| Воспроизводимость | Всегда |
| Автотест | `4. Known defects / API-BUG-004 Create pet without required fields` |

## Шаги воспроизведения

```bash
curl -i -X POST https://petstore.swagger.io/v2/pet \
  -H "Content-Type: application/json" \
  -d '{}'
```

## Фактический результат

```
HTTP/1.1 200 OK

{"id":9223372036854775807,"photoUrls":[],"tags":[]}
```

1. Питомец создан без обязательного поля `name` (в спецификации `required: ["name", "photoUrls"]`).
2. Сервер сам назначил id `9223372036854775807`, это максимальное значение int64.
3. Этот id больше `Number.MAX_SAFE_INTEGER` (9007199254740991). В JavaScript после `JSON.parse` он превращается в `9223372036854776000`. Запрос `DELETE /v2/pet/9223372036854776000` из Postman вернул `404`: клиент на JavaScript не может удалить созданную запись по id из ответа.

## Ожидаемый результат

Запрос без обязательных полей отклоняется ошибкой валидации (`405 Invalid input` по спецификации), запись не создается.

## Дополнительно

Пункт 3 нашелся при написании автотеста: очистка тестовых данных удаляла не ту запись. В коллекции id теперь берется из сырого текста ответа. Каждый повторный запрос `{}` перезаписывает одну и ту же запись с id `9223372036854775807`. Priority High: фронтенд на JavaScript получает искаженный id без ошибки.
