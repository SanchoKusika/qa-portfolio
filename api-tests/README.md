# API-тесты: Swagger Petstore

Коллекция Postman для публичного учебного API [Swagger Petstore](https://petstore.swagger.io/), базовый адрес `https://petstore.swagger.io/v2`. Ожидаемое поведение берется из [спецификации Swagger](https://petstore.swagger.io/v2/swagger.json).

Коллекция запускается автоматически в GitHub Actions через Newman: при изменениях в папке `api-tests/` и раз в неделю.

## Состав

| Папка | Запросов | Что проверяется |
|---|---|---|
| 1. Pet CRUD | 7 | Полный цикл питомца: создание → чтение → изменение → проверка изменений → поиск по статусу → удаление → 404 после удаления |
| 2. Store | 5 | Инвентарь склада, создание, чтение и удаление заказа, 404 после удаления |
| 3. Negative | 5 | Несуществующие id, запрос без тела, невалидный JSON, удаление несуществующего питомца |
| 4. Known defects | 6 | Поведение по спецификации, которое сервер нарушает. Тесты падают, пока дефекты не исправлены. Описание: [bug-reports/api](../bug-reports/api/README.md) |

Папки 1–3: 17 запросов, 59 проверок, все проходят. Папка 4: 13 проверок, 7 падают на найденных дефектах.

## Что используется

- **Цепочка запросов через переменные коллекции.** Pre-request script генерирует уникальный `petId`, следующие запросы берут его из `{{petId}}`. Тесты не зависят от чужих данных на общем стенде.
- **Проверки `pm.test`** в каждом запросе: статус-код, заголовки, значения полей, сравнение с отправленными данными.
- **Проверка JSON-схемы** (`pm.response.to.have.jsonSchema`) для питомца и заказа, включая допустимые значения `status`.
- **Общая проверка на уровне коллекции:** время ответа меньше 3000 ms для каждого запроса.
- **Очистка тестовых данных:** если сервер создал запись, несмотря на невалидные данные, тест удаляет ее через `pm.sendRequest`.
- **Проверка сохранения, а не только ответа:** после `PUT` идет отдельный `GET`, который подтверждает, что изменения записаны.

## Как запустить

**В Postman:** Import → файл [`petstore.postman_collection.json`](petstore.postman_collection.json) → правый клик по коллекции → Run. Окружение не нужно: базовый адрес задан переменной коллекции `baseUrl`, ключи не требуются.

**Из командной строки** (нужен Node.js):

```bash
# рабочее поведение, как в CI
npx newman run api-tests/petstore.postman_collection.json --folder "1. Pet CRUD" --folder "2. Store" --folder "3. Negative"

# тесты на известные дефекты
npx newman run api-tests/petstore.postman_collection.json --folder "4. Known defects"
```

## CI

Workflow: [`.github/workflows/api-tests.yml`](../.github/workflows/api-tests.yml).

- Шаг 1 запускает папки 1–3. Если они падают, сборка красная.
- Шаг 2 запускает папку известных дефектов, но на результат сборки не влияет. Если дефект исправят, в отчете это будет видно.
- Отчеты JUnit сохраняются как артефакт сборки `newman-reports`.
